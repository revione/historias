What happens inside a Transformer when you send it a prompt
A technical guide to architecture, weights, and the opacity of commercial models

When a model receives a prompt, the first thing that happens is tokenization: the text is split into tokens, fragments that can be whole words, pieces of words, or symbols. Each token has an integer identifier, and each identifier has an associated vector in a table called the embedding matrix. That table is the model's first family of weights: it converts discrete tokens into continuous vectors. For LLaMA 7B, each vector has dimension d = 4,096. For LLaMA 70B, d = 8,192. That dimension, called hidden size, is the width of the model.
Positional information is added to token embeddings, because attention by itself does not distinguish the order of the sequence. Classical models use learned or sinusoidal positional embeddings. Modern models like LLaMA use RoPE (Rotary Position Embedding), which rotates queries and keys according to their position before calculating attention. The idea, in any variant, is that the token's position in the sequence enters as information inside the vector.
Once the tokens have been converted into vectors with their position encoded, they enter the stack of layers. A Transformer layer is a block of operations that receives a tensor of size n × d — where n is the number of tokens and d is the model dimension — and produces a tensor with the same shape. The shape remains constant throughout the whole stack. What changes are the numerical values inside the vectors. The vector for token 5 after layer 1 is not the same vector after layer 12: it has been transformed by the weight matrices of each intermediate layer.
The structural reason the dimension is preserved is the residual connection. Each layer has the form:
x_new = x_old + Block(x_old)
That sum requires the same dimension in both terms. The residual connection serves two functions: it stabilizes the gradient during training, and it makes each layer add information to the existing vector instead of replacing it. The vector that comes out of layer 30 contains traces of what entered layer 1, plus all the modifications accumulated by the intermediate layers. Before each sub-block there is also a normalization layer — LayerNorm in classical models, RMSNorm in modern models like LLaMA — which rescales the vector to keep its magnitude under control and prevent values from exploding as they pass through many layers.
Inside each layer there are two sub-blocks with different functions, and here the two main families of weights in the body of the model appear.
The first sub-block is attention. This is where tokens communicate with each other. For each token, three projections of its vector are calculated through three matrices: W_Q produces the query, W_K the key, W_V the value. Attention then calculates, for each pair of tokens (i, j), a score as the dot product between the query of i and the key of j. That score measures how relevant j is to i according to the criterion learned by the matrices. In generative models like GPT or Claude, a causal mask is also applied: token i can only attend to tokens in positions j ≤ i, never to the future. This is what allows the model to be autoregressive — to predict the next token without having seen the following tokens during training. After a softmax normalizes the scores into a probability distribution, the output vector for token i is a weighted combination of the values of all accessible tokens, weighted by the scores. A fourth matrix, W_O, mixes the outputs of the different attention heads and projects the result back to dimension d. The function of attention is mixing across positions: the vector for token 5 absorbs information from tokens 1, 2, 3, 4.
The second sub-block is the feedforward. Here there is no communication between tokens — each vector is processed in isolation. A matrix W₁ projects the vector from dimension d to a larger internal dimension d_ff, typically between 2.5× and 4× the model dimension. A nonlinearity is applied component by component. Another matrix, W₂, projects back to dimension d. Modern models use three matrices with a gating mechanism (W₁, W₂, W₃ in SwiGLU) instead of two, but the logic is the same: expand, apply nonlinearity, contract. The function of the feedforward is transformation by position.
This separation is the fundamental idea of the Transformer. Attention communicates, feedforward processes. Communicate → process → communicate → process, layer after layer. Without attention, tokens would never see the others and the model could not understand context. Without feedforward, the expressive capacity of the model would drop drastically — attention by itself, even with softmax, does not compose functions rich enough to learn language.
There is also a third family of weights, at the ends of the model. The embedding matrix W_E at the beginning, already mentioned. And at the end, the unembedding matrix W_U, which takes the output vector from the last layer and projects it to a vector the size of the vocabulary — typically between 32,000 and 128,000 dimensions. That final vector is the logits: a score for each possible token in the vocabulary.
Applying softmax over the logits gives the probability distribution of the next token, but that distribution is still not text. To produce a concrete token, the model has to sample from it, and this is where the parameters you probably know come in: temperature scales the logits before softmax (low temperature concentrates mass on the most likely tokens, high temperature spreads it out); top-p filters to the tokens whose cumulative probability covers a certain threshold; top-k restricts to the k most likely tokens. The choice of the next token is then a random sample from the filtered distribution. Models like Claude Opus 4.7 directly block non-default values of temperature, top_p, and top_k through their API, forcing a fixed sampling policy — control over generation moves from sampling toward the prompt and reasoning-effort levels.
Each layer has its own complete set of attention and feedforward matrices. They are not shared across layers. LLaMA 7B has 32 layers, which means 32 distinct W_Q matrices, 32 distinct W_K matrices, 32 distinct sets of feedforward matrices — all with values learned independently during training. LLaMA 70B reaches 80 layers. The embeddings W_E and the unembedding W_U are unique for the whole model, and sometimes they are tied, using the same matrix for both operations.
This leads to the difference between layers. Empirically, across many models analyzed with interpretability techniques, early layers (the first 15-20% of depth) tend to process low-level features: token patterns, spelling, language identification, basic syntactic structure. Middle layers do the heavy work of understanding: they combine syntactic information into semantic structures, resolve references, identify relationships between entities. Late layers specialize in producing the output: they integrate all accumulated information and channel it toward a concrete prediction of the next token. This hierarchy is not rigid or perfectly separable, but it is a consistent pattern. The reason stacking many layers works is this: each layer can perform a relatively simple transformation, and the composition of many simple transformations allows progressively more abstract representations to be built.
Up to here, the architecture. The missing question is when all of this runs in parallel and when it does not, because half the real cost of the system is there.
Inference has two phases with opposite behaviors.
The prefill phase processes the complete prompt. If the prompt has 2,000 tokens, all 2,000 enter the model simultaneously. Each layer processes the whole n × d matrix in a single pass. Matrix-matrix multiplications are massively parallelized on GPU, and inside a layer the feedforward is trivially parallel by position — each of the 2,000 tokens is processed at the same time. Attention is also computed in parallel: the score matrix Q · Kᵀ is calculated at once for all valid pairs (i, j), and here it does have size n × n. This phase saturates the hardware and is efficient per token. It is also where attention scales quadratically with context length: for n = 1,000, one million scores per head per layer; for n = 10,000, one hundred million; for n = 100,000, ten billion.
But between layers there is sequential dependency. Layer 5 cannot start before layer 4 finishes, because it needs its output as input. The parallelism is intra-layer, not inter-layer. The stack is traversed from top to bottom, layer by layer, even though inside each layer everything that can be parallelized is done at once.
The decode phase is output generation. Here the behavior is inverted. The model generates one token at a time, and it cannot generate token n+1 without having generated token n — that is the autoregressive nature. At each decode step, a single pass through the whole stack of layers produces one new token. The GPU is underutilized because it processes a single position. That is why generation is slow compared with prefill, and why models seem to "take time" after the first moment of thinking.
For decode to be viable, the KV cache exists. During prefill, the keys and values calculated in each layer are stored in GPU memory. During decode, for the new token only its own Q, K, V are calculated; the attention of the new token against the whole context is then a 1 × n operation per head per layer, not n × n. In other words: with KV cache, each decode step is linear in context length, not quadratic. Without that cache, the whole context would have to be recalculated from scratch at every step, and generation would become quadratic per generated token.
The price of the KV cache is memory. In a classical LLaMA 7B with full multi-head attention in fp16 format, each context token occupies approximately 0.5 MB of cache; a context of 100,000 tokens would consume about 50 GB just in cache. Modern models reduce this cost with attention variants that share keys and values across heads — Grouped Query Attention (GQA) in LLaMA 2/3 and Mistral, Multi-Query Attention (MQA) in PaLM — in addition to cache quantization and optimized kernels such as FlashAttention. In production, the real KV cache can be several times smaller than in the classical version. But the structural idea remains: long contexts are expensive mainly because of the memory the cache requires to keep alive throughout the entire generation, not only because of compute.
In production servers, models also do not process one conversation at a time — they run continuous batching, mixing prefills from some users with decodes from others to saturate the GPU as much as possible. That explains why the cost per token in the API is much lower than the cost of serving a model dedicated to a single user: the economics depend on how much the GPU can be amortized across multiple simultaneous sessions.
All the mechanics above describe the Transformer as a public concept. But when we talk about concrete commercial models, what we know changes drastically.

A note on commercial models
Everything above is grounded in LLaMA as the technical reference because it is the only frontier model whose architecture is fully published. When talking about Claude Opus 4.7 or GPT-5.5, the situation changes. What is publicly confirmed is limited.
For Claude Opus 4.7, released by Anthropic on April 16, 2026, the official documentation confirms a one-million-token context window at the standard API price, with no long-context surcharge, and availability as claude-opus-4-7 in the API. Anthropic has also documented that Opus 4.7 introduces a new tokenizer that can use between 1.0× and 1.35× more tokens for the same text compared with Opus 4.6, that it adopts "adaptive thinking" as a reasoning mode by removing the manual thinking budgets (budget_tokens) that existed in earlier versions, and that it incorporates a new xhigh effort level between high and max. Control over reasoning does not disappear — it shifts from manual budgets toward effort levels and task budgets that the model interprets dynamically.
What Anthropic's official documentation does not publish are the architectural details: number of layers, hidden dimension, number of heads, activation function, attention variant, parameter count. Third-party pages such as model aggregators describe Opus 4.7 as a "dense transformer with multi-head attention and absolute positional embeddings", but that information does not appear in Anthropic's official material — it comes from community inferences and leaks, and should be treated as such. External analyses assume that the model has tens of billions of parameters and that it remains a dense transformer (not a mixture-of-experts), but none of those points is confirmed by Anthropic.
For GPT-5.5, released by OpenAI on April 23, 2026, what is confirmed is that it inherits the architecture of the GPT-5 family, described by OpenAI as a system with a fast model for standard queries, a deep reasoning model for complex problems, and a real-time router that decides which one to use according to the conversation, complexity, and tools required. Whether that same structure remains exactly the same in GPT-5.5 or has changed internally is not documented — external analyses describe GPT-5.5 more as an improvement in post-training and inference than as a new base model. Reasoning-effort levels range from none (minimal latency, no reasoning) to xhigh (extended reasoning for demanding asynchronous tasks). API context is one million tokens, with a 2× surcharge on input and 1.5× on output when the prompt exceeds 272K tokens — an explicit contrast with Opus 4.7, which applies no surcharge. The parameter count, number of layers, internal dimension, and attention variant used are not public.
This means that, although the mechanics described here are the base on which these models are built, the concrete details of each one — how many layers, how many heads, which optimized attention variant they use, which activation functions, how they handle long contexts at reasonable cost — are under each company's trade secrecy. The part we can affirm is the mathematics of the standard Transformer, valid as a base description. What cannot be affirmed are the specific numbers, not even with certainty which architectural variants are used in each model.
There are also new technologies these models seem to be using — attention variants that reduce the cost of KV cache, forms of reasoning through extra layers, internal routing mechanisms, persistent prompt-caching techniques — and that are mentioned in releases without detailed technical documentation. What exactly is behind Anthropic's "adaptive thinking", or OpenAI's router, at the level of architectural modifications? Outside the two companies, it is not known.
This post is based on what we currently know: the Transformer architecture published in 2017, the variants documented in open models like LLaMA, and the mechanistic interpretability literature that has partially mapped how computation is distributed across layers. What happens inside closed frontier models is an extension of that base, but with specific modifications their developers have not published. We work with a mental model that is correct in its fundamentals and opaque in its details. That does not invalidate what we know — but it is worth keeping in mind every time someone claims with certainty what Claude or GPT does inside.
